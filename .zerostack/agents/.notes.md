These notes are specific to the mini-agent repository. Apply only the section relevant to the delegated objective; repository instructions and current source remain authoritative.

### Rust lifecycle

- The production crate is the repository root. Follow `AGENTS.md`: format with `cargo fmt`, test with `cargo test`, and build/install with `cargo install --path . --debug`; never use the `spike/` research crate as a production target.
- Check feature-default and no-default-feature behavior where a change crosses `#[cfg]` boundaries. Release work also spans the root crate, CI workflows, documentation, and `editors/vscode` packaging.

### Async and concurrency

- High-risk ownership paths include the main agent loop, ACP session tasks, hook subprocesses, background shell jobs, the JS worker supervisor, and worktree operations. Distinguish cancellation request, future drop, descendant reaping, and durable outcome reconciliation.
- Process creation is centralized by the platform creation boundary. Confirm new subprocess paths participate rather than assuming a Tokio or standard-library spawn is sufficient.

### Unsafe code and containment

- For JS worker, broker, protocol, or sandbox changes, use the canonical Phase 6 checklist in `docs/specs/phase-6-brokered-js-runtime.md`. Do not create or rely on a second invariant list.
- Review platform implementations under `src/sandbox/worker/` against their actual OS guarantees and the parent broker under `src/extras/js/`; a green source-only test is not a substitute for the relevant target-host probe.

### Application security

- Important trust boundaries include project configuration and prompts, hook envelopes and subprocesses, ACP/MCP input, filesystem capability bindings, session persistence, learned skills, and the JS effect broker.
- Trace authorization through the captured workspace and permission checker. Treat paths in `src/extras/hooks/`, `src/extras/acp/`, `src/extras/mcp/`, and `src/extras/js/` as leads, not proof that a control applies to every caller.

### VS Code extension

- The extension lives under `editors/vscode`. Verify its manifest, TypeScript sources, packaging scripts, platform artifact selection, ACP stdio client, tests, and produced VSIX together.
- Repository build artifacts under `editors/vscode/dist/` may be stale. Use the package scripts and smoke procedure documented in that directory before making a packaging claim.
